=== TRIBE SOCIAL ARCHITECTURE ===

1. DATA NORMALIZATION & PERSISTENCE
   - Single source of truth: MongoDB.
   - Separate queries for /feed (followers) and /user/:userId (profile specific).
   - Author field enforced on every Post document.

2. ATOMIC POST ACTIONS
   - Likes and comments update specific documents by ID.
   - Backend returns full updated object; Frontend maps ID to state for instant, targeted update.
   - Prevents "Global Like" bug by ensuring per-post state management.

3. REAL-TIME NOTIFICATIONS
   - Schema: Persists recipient, sender, type, and entityId.
   - Trigger: Follow, Like, Comment, and Tribe Join actions create DB entry.
   - Socket: Emits to recipient's private room. UI toasts and increments bell count.

4. USER INTERACTION & CACHING
   - Profiles fetch on-mount based on URL/Viewing context.
   - User banners now correctly fetched via full User object hydration in ProfilePage.
   - Local state reconciliation on every API response.

5. AI ASSISTANT (CHUK)
   - Navigates to a targeted conversation window.
   - Proxies through Gemini API with custom mascot persona.
