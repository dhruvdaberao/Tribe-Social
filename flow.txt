=== TRIBE SOCIAL FINAL PRODUCTION ARCHITECTURE ===

1. DATA HYDRATION (Layered Fallback)
   - L1 (UI Cache): Immediate load from 'tr_cache_*' localStorage keys. No spinners.
   - L2 (Background Refresh): Silent API fetch on every page load/mount.
   - L3 (Real-time): Socket.io pushes updates (new posts/messages) to state without refresh.

2. MEDIA PIPELINE (Cloudinary-to-Mongo)
   - UPLOAD: FE sends Base64 -> Backend -> Cloudinary.
   - STORAGE: Cloudinary returns URL -> Backend saves URL to MongoDB field 'imageUrl'.
   - NEVER: Store base64 in MongoDB. This prevents document size limits and 502 errors.

3. FEED & LIST PERFORMANCE
   - INDEXING: Compound indexes on (user: 1, createdAt: -1) ensure O(log n) lookups.
   - OPTIMIZATION: Mandatory .lean() on all find() queries to bypass Mongoose hydration overhead.
   - PAGINATION: Enforced 10-15 item limit per page to reduce payload size.

4. CHAT & REALTIME
   - ROOMS: On connect, FE joins unique 'dm-id-id' and 'tribe-id' rooms.
   - RELIABILITY: Socket emits are non-blocking. If DB write fails, socket remains unaffected.
   - CACHE: Messages are persisted in state; reload fetches last 50 only.

5. FAULT TOLERANCE
   - EMPTY DB: All GET APIs strictly return empty arrays [] instead of null/500.
   - TIMEOUTS: Axios timeout set to 20s with a single auto-retry for Render spin-up.
   - GHOST DATA: Filters verify that populated 'user' field exists before sending to FE.

=== END-TO-END FLOW SUMMARY ===
Action (Post/Msg) -> Optimistic UI Update -> API Call (Cloudinary + DB) -> Socket Broadcast -> Hydrate Recipients.
