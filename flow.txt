=== TRIBE SOCIAL PRODUCTION STABILIZATION ARCHITECTURE ===

1. SOURCE OF TRUTH (BACKEND)
   - MongoDB: Stores all data. Lean queries (.lean()) and indexes ensure <200ms DB responses.
   - Cloudinary: Media storage. Frontend uploads base64 -> Backend pipes to Cloudinary -> URL stored in DB.

2. FAST-LOAD STRATEGY (FRONTEND CACHING)
   - Layer 1: Hydration from 'cache_posts', 'cache_users', 'cache_tribes' in localStorage on mount. UI appears instant.
   - Layer 2: Background Fetch. App makes fresh API calls immediately after mount.
   - Layer 3: State Reconcilliation. API response silently updates local state and cache.

3. INSTANT FEEL (OPTIMISTIC UI)
   - Action (Post/Like/Follow/Message): UI updates state immediately.
   - Backend Sync: API call happens in background.
   - Fail-Safe: On error, a rollback is triggered and toast alert notifies user.

4. REAL-TIME ENGINE (SOCKET.IO)
   - Connections: Users join their own private room (userId) for notifications and shared rooms for DMs (dm-convoId) and Tribes (tribe-id).
   - Events: 'newMessage', 'newPost', 'newNotification' trigger state updates without page refetching.

5. PERSISTENCE ON REFRESH
   - Token & User: JWT stored in localStorage. AuthProvider hydrates user state.
   - Cache: Feed and lists use Layer 1 (Cache) to show content while server is cold-starting.

=== DATA FLOW SUMMARY ===
Create Post -> Local State -> Cloudinary -> MongoDB -> Socket Broadcast -> Recipients.
